## 环境与计时定义

Windows 11 家庭版中文版 10.0.26200，amd64；Intel Core Ultra 5 336H，系统报告 12 核 / 12 逻辑处理器；可见内存 33,873,752,064 字节（约 31.55 GiB）。Temurin 21.0.12.1+1、Maven 3.9.9。单 JVM、单线程，默认 JVM/GC，未主动触发 GC，运行暂停计入耗时；不是并发锁座实验。

使用 `System.nanoTime` 包住单次完整 `recommend` 调用，包括布局排序、分段、窗口/孤座过滤、BigDecimal 中心评分、所有候选排序和截断。不计数据生成、预热、Java 源文件编译、消费结果和文件写入；不含 Spring、HTTP、MySQL 或网络。各规模预热 50 次，正式采样 100 次，分位数使用 nearest rank。

## 数据生成

自行构造虚拟布局：2 区域，每排 20 座、2 个等长过道段，3 个票档按整排循环，5% 不可售概率。人数为 2，返回上限为 5，禁止新孤座；全部票档启用，无区域/票档筛选。

基础种子 `20260928`，每规模有效种子为基础种子 + 总座数，使用 Java Random 顺序生成状态，再以有效种子 XOR `0x5DEECE66D` 打乱输入。1,000 / 5,000 / 10,000 座分别对应每区 25 / 125 / 250 排。每次测量使用相同布局；实际不可售数是概率采样结果。完整生成参数、有效种子和输入 SHA-256 保存在汇总 CSV。

## 实测结果

| 总座数 | AVAILABLE 座数 | 合法窗口数 | 返回组数 | 平均耗时 ms | 中位数 ms | P95 ms |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 953 | 591 | 5 | 1.041 | 0.923 | 1.476 |
| 5,000 | 4,754 | 2,941 | 5 | 3.612 | 3.333 | 4.774 |
| 10,000 | 9,515 | 5,929 | 5 | 7.511 | 7.106 | 9.607 |

这组观测仅表示该机器、该布局和人数下的纯算法耗时。规模主要靠增加排数扩展，没有测试长排、大人数、特殊票档分布、HTTP 延迟、数据库吞吐或生产容量。不能由它得出 Redis、MQ 或并发能力的结论。

`limit` 在生成并排序全部候选后才截断，不限制中间计算。令 N 为座位数、q 为人数、K 为合法窗口数，当前时间复杂度为 `O(N log N + Kq + K log K)`，空间为 `O(N + Kq)`。后续若真实长排/大人数需求导致成本过高，可在保持输出规则一致的前提下比较滑动求和和 Top-K；本轮不引入这些优化。
