# 场次配置与销售启停方案

- 日期：2026-10-05
- 状态：项目负责人于 2026-10-05 确认建议方案，决策见 ADR-0006；实际测试结果另行记录
- 范围：第二周场次配置、开售/暂停/恢复、票档启停，不扩展到交易或登录

## 用例与验收

运营人员创建 DRAFT 场次后调整时间、孤座规则、已有票档的名称/价格，以及已有场次座位的票档/可售性，再开放销售。一次配置请求中的所有修改整体提交；不读取或重新复制物理模板，不改变座位 ID 或布局。

销售状态沿用 DRAFT → ON_SALE → STOPPED → ON_SALE。first_opened_at 只在第一次开售写入，以后保持。曾开售场次不能编辑上述配置；暂停后仍然冻结。票档 enabled 是独立的新购买开关，任何销售状态下都可启停，不改座位快照。

建议补齐的操作边界：

- 通过 PUT 设置目标销售状态，重复设置当前 ON_SALE/STOPPED 返回当前结果，不重复写首次开售时间；不能退回 DRAFT，也不能从 DRAFT 直接暂停。
- 开售/恢复时至少存在一个 AVAILABLE 且票档 enabled 的座位，否则返回 409；票档停用仍允许全部停用。该检查只用于开售操作，未来下单仍需重新检查销售状态和票档开关。
- 座位可售性仅在首次开售前配置，避免绕过未来的锁座和已售状态；开售后使用场次或票档开关控制新购买。
- 本轮修改已有票档和座位，暂不增加票档新增/删除、座位增删/重生成、售票时间窗口或场次取消。

## 并发问题、备选和建议

若改价请求读到 DRAFT 后暂停，另一个事务已经开售，前者恢复后继续写价，就会突破冻结边界。只包一层普通事务或先查状态仍不能解决这一交错。

| 方案 | 行为与代价 |
| --- | --- |
| 场次行锁（建议） | 管理写操作在同一本地事务中先 SELECT session FOR UPDATE，读最新状态再校验和写入；同场次管理操作串行，不同场次仍可并发；无需新字段 |
| 版本号与条件更新 | 检测冲突后让调用方重读重试；可减少等待，但需新增版本字段，并协调票档/座位更新与版本检查回滚 |

建议配置编辑、销售启停、票档启停都先锁所属场次行，随后按固定顺序修改本场次数据。锁保持到事务提交/回滚。配置事务内同时改 session、price_tier、session_seat，inventory 服务加入调用方事务；不跨模块访问 Mapper。创建场次读取物理模板仍沿用 ADR-0005 的普通一致性读。

## 接口草图

| 接口 | 输入与行为 |
| --- | --- |
| PUT /api/sessions/{id}/configuration | 时间、孤座规则、票档编辑列表、座位配置列表；列表可空表示该类对象不修改；必须都是本场次已有 ID |
| PUT /api/sessions/{id}/sales-status | salesStatus 为 ON_SALE 或 STOPPED；合法迁移或相同目标 |
| PUT /api/sessions/{id}/price-tiers/{tierId}/enabled | enabled 布尔值；不改名称/价格快照 |

座位配置使用场次座位 ID（不是来源模板 ID）、可空 priceTierId 和 available 布尔值。AVAILABLE 必须有本场次票档；UNAVAILABLE 允许清空三个价格字段。票档名称/价格变更必须同步更新所有关联座位（含不可售位）的价格快照。稳定代码、来源 ID 和布局字段不可修改。

配置请求示例（ID 替换为查询到的本场次实际 ID）：

~~~json
{
  "startsAt": "2027-01-15T20:00:00+08:00",
  "admissionOpenAt": "2027-01-15T19:00:00+08:00",
  "admissionCloseAt": "2027-01-15T19:55:00+08:00",
  "forbidNewOrphan": true,
  "priceTiers": [{"id": 1, "name": "调整后 A 档", "price": 420.00}],
  "seats": [{"id": 56, "priceTierId": 1, "available": true}]
}
~~~

单独修改时间或孤座规则时，priceTiers/seats 传空列表。重复 ID 拒绝，而不是按列表最后一项覆盖；防止请求中的配置歧义。

## 验收场景与执行证据

以下场景已经实现并在 2026-10-05 的完整测试中通过；测试类、数量、环境和开发库演示记录见[第二周周报](../progress/week-02.md)。

1. DRAFT 配置时间、票档和座位整体成功，票档更新同步所有关联价格快照，其他场次/模板保持不变。
2. 无票档不可售位直接启用被拒绝，补齐本场次票档后成功；未知/重复/跨场次 ID、无效时间拒绝且不留下部分修改。
3. DRAFT→ON_SALE、ON_SALE→STOPPED、STOPPED→ON_SALE 及重复目标；first_opened_at 保持，非法迁移不写入。
4. 开售后及暂停后配置编辑都被拒绝；票档启停不改任何座位布局/价格/状态。
5. 真实写入票档与座位之后注入异常，三类配置更新全部回滚。
6. 使用两个真实事务和协调信号验证两种先后顺序：改价先持锁则开售采用提交后的价格；开售先持锁则改价等待后看到已开售并拒绝。无真实 sleep 碰运气。
7. 真实 HTTP 验证参数、404/409、返回值和 OpenAPI；保存可重复本机演示脚本。
