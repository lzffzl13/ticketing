# 第三周座位图与连座推荐方案

- 日期：2026-10-05（Asia/Shanghai）
- 状态：项目负责人于 2026-10-05 确认建议方案，决策见 ADR-0007；实际验证另行记录
- 范围：只读座位图、确定性连座推荐、共用选座规则、测试、算法基线与演示；锁座下单在第四周实现

## 用例与验收

消费者查询完整场次座位图，按人数以及可选区域、票档获得候选。所有候选满足同区域、同排、同票档、连续座号、不跨过道，且默认不制造新孤座。查询不写库存，也不承诺候选在后续下单时仍有效。

验收包括至少 15 个规则测试、真实 MySQL/HTTP 查询验证、快照隔离、销售/票档开关、重复查询无写入，以及可重复的 API 演示和不同规模的算法基线。自动化已通过与场景已设计分别记录。

## 已确认规则

- 座位图来自 session_seat 快照，保留 UNAVAILABLE、HELD、SOLD 座位的布局；不读当前场馆模板。
- seatStatus 描述库存；场次销售状态和票档 enabled 独立影响购买资格，不改库存状态。
- 推荐只在 ON_SALE 时提供，库存为 AVAILABLE 且票档启用的座位才能参与。
- 连座和孤座边界沿用 ADR-0002。已有孤座可以购买；场次可关闭禁止制造新孤座。
- 推荐不等于锁座，最终下单必须重新读取最新状态并原子校验整组选座。
- Q-05 登录方案留待个人数据/交易鉴权前确认；本轮沿用第二周仅监听本机的演示 API，不实现账号或权限。

## 新增决策的备选与建议

| 问题 | 备选方案 | 建议及取舍 |
| --- | --- | --- |
| 一次查询的一致性 | 多次独立查询；一个只读 REPEATABLE READ 事务 | 后者让场次、票档和座位读取同一版本，避免拼出未曾存在的组合；不使用 FOR UPDATE，查询完成后仍可能过期 |
| 连座算法 | 实时分段扫描；位图；预计算候选 | 首版实时扫描，排序后切分连续可售段，用人数大小的窗口枚举；容易解释，不提前引入缓存与维护成本 |
| 候选优先级 | 只按排座；区域中心距离；前排优先 | 先按区域展示顺序；同区域按候选中心到区域几何中心的距离平方升序，再按排排序、起始座号、座位 ID 破同分；不假设消费者偏爱前排 |
| 孤座复用 | 推荐和下单各写一份；一个纯规则组件 | inventory 中共用 SeatSelectionRules；输入完整座位布局与所选 ID，检查连座和新孤座。第四周把该组件放入最终锁座事务，第三周只验证规则和重新读取场景 |

区域中心采用该区域全部快照坐标的边界框中心：`((minX+maxX)/2, (minY+maxY)/2)`。候选中心为各座位坐标的算术平均，使用 BigDecimal 确保同输入排序稳定。不可售、已锁定、已售座位仍参与几何中心计算，防止库存变化移动偏好中心。不同区域坐标独立，先使用区域展示顺序，不将它们解释为共同物理坐标。

首版不添加用户位置偏好或推荐非连座组合。消费者关闭连座要求时可手动自由选座；最终选座校验仍执行孤座规则。推荐人数只要求正整数，不把返回条数上限当成购票人数上限。

## 接口与返回语义

| 接口 | 行为 |
| --- | --- |
| GET /api/sessions/{id}/seat-map | 返回场次销售状态、孤座开关、查询时间、区域/排/完整座位、库存状态、票档快照、票档启用状态和 selectable 派生值 |
| GET /api/sessions/{id}/recommendations | quantity 必填正整数；areaCode、priceTierId 可选；limit 默认 5，范围 1–20；返回候选座位、总价、中心距离及说明 |

未知场次返回 404，非法参数或不属于场次的筛选条件返回 400，未开售/已暂停场次请求推荐返回 409；合法筛选没有合适候选返回 200 和空数组。座位图在 DRAFT/STOPPED 也可查询，但 selectable 全为 false。

推荐附带分段数量、人数不足的段数、因新孤座排除的窗口数、全部合法候选数，帮助解释为何没有候选。响应标记 `reservationMade=false`，候选数量截断只影响展示，不改变算法规则。查询时间是 Clock 提供的响应标记，不是锁定期限或数据库版本号。

票档关闭影响推荐可用性，但不把 AVAILABLE 座位改成 UNAVAILABLE。孤座结构检查仍按完整库存状态和固有票档边界进行；票档开关不会拆开同票档内部的可售段。

## 实现和验证顺序

1. inventory 纯选座规则与人工可推演的边界测试（既有已确认规则，可直接推进）。
2. 按已确认方案实现 catalog 查询编排与 inventory 规则算法；不跨模块调用 Mapper。
3. 座位图/推荐 MySQL 集成测试和真实 HTTP 契约；推荐后状态变化的测试重新读库，再校验旧候选；不称其为原子锁座测试。
4. 可重复演示脚本、算法输入/输出/规则顺序说明。
5. 固定生成参数与种子的 1,000 / 5,000 / 10,000 座单线程纯算法实验，记录预热、样本、平均耗时、机器/JDK；不把算法耗时当成 HTTP 或数据库性能。
6. 每个闭环讲解关键代码并更新第三周进度，负责人学习验收单独保留。

本方案不修改七表结构、不新增 Redis/MQ，不决定第四周锁座并发或幂等方案。第三周未实现的最终原子锁座在进度文档明确列为后续任务。
