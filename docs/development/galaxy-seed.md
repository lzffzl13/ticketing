# 星河艺术中心：246 座主演示数据

## 运行与数据

应用按 [本地环境](local-environment.md)启动后执行：

~~~powershell
.\scripts\seed-galaxy.ps1
~~~

默认连接 http://127.0.0.1:8080，命名空间 DEMO。可指定 -BaseUrl、-Namespace 和带时区的 -BaseTime；只接受本机 HTTP。所有场馆、演出与座位均为自行构造的虚拟数据。

| 对象 | 本命名空间生成的数量 / 内容 |
| --- | --- |
| 场馆 | VENUE-GALAXY-DEMO，星河艺术中心 |
| 区域 / 排 | 一层池座 ORCHESTRA 8 排、楼座 BALCONY 6 排 |
| 座位模板 | 246 座，242 座默认可售 |
| 票档 | 每场优选票 580、标准票 380、楼座票 280；共 9 个独立票档 |
| 场次 | SESSION-DRAFT-DEMO、SESSION-ON-SALE-DEMO、SESSION-CHECKIN-DEMO |
| 座位快照 | 每场 246 座，共 738；每场 4 个不可售位不配置票档 |
| 演示账号 | 0；账号和令牌随 Q-05 实现，不把未实现的登录写成已完成 |

池座 A-C 排为优选票，D-H 排为标准票；楼座全部为楼座票。不可售位是池座 H1/H22、楼座 F1/F16。完整排宽与规则见[数据设计](../data/seed-data-design.md)。

每个区域独立使用逻辑坐标：行居中于 x=0，纵坐标为该区域排排序；左右半排分别向外移动 0.75，使中央相邻两座距离为 2.5（额外过道空隙 1.5）。普通相邻座距离为 1。实际连座边界仍依赖 aisle_segment，不能只看坐标距离。

## 入口与主流程

- [seed-galaxy.ps1](../../scripts/seed-galaxy.ps1)：按业务代码定位、预检已有数据、创建缺失对象、生成场次、开售与输出摘要。
- [galaxy-seed-data.ps1](../../scripts/galaxy-seed-data.ps1)：声明布局/票档/相对时间、生成座位输入，并校验模板及快照完整性。
- [week2-api.ps1](../../scripts/week2-api.ps1)：复用已有本机限制及 UTF-8 JSON 请求方式。

脚本先查询三个已知场次、场馆、演出、区域和模板。所有已存在对象都预检通过后，才创建缺失对象；先校验完整布局和价格，再将需要售票的 DRAFT 场次通过销售 API 开售。脚本调用与普通业务请求相同的服务，不直接 INSERT 或绕过冻结规则。

```mermaid
flowchart LR
    A[按代码查询并预检] --> B[创建缺失场馆与布局]
    B --> C[逐场创建独立票档与快照]
    C --> D[校验每场246座及价格]
    D --> E[售票与入场演示场次开售]
    E --> F[输出基准时间和数量]
```

创建每个场次仍由 SessionService 的单个本地事务完成。246 座会由 InventoryService 分成 200+46 两批写入，这两批共用同一个事务。整份种子包含多个 HTTP 请求，整体没有一个跨请求事务：此前成功的对象在后续失败时保留，重跑校验并续建，而不是自动删除或强行覆盖。

## 时间、重跑与异常分支

首次运行只读取一次 UTC 基准时间，并截取到 MySQL DATETIME(6) 的微秒精度。草稿在基准后 30 天开场，售票场次在 7 天后，入场演示场次在 30 分钟后；入场开放/截止为开场前 60/5 分钟。

有任意已保存的场次时，从它的 starts_at 减去固定偏移恢复基准，核对其他场次时间。重跑即使提供不同 -BaseTime 也不刷新已保存时间；全部已完成时不修改任何记录，包括首次开售和 updated_at。入场窗口会随实际时间过去；需要新的当前窗口时使用新 -Namespace，不修改已开售场次。

场馆/布局/时间/票档/快照与固定基线有差异，或场次被手工暂停时，脚本报错并保留改动；不解除冻结、不补造已完成场次缺失的来源模板。固定种子校验要求恢复原基线，不代表业务禁止维护模板；合法维护后需要独立的新种子命名空间。

如果预定为 ON_SALE 的场次已创建为 DRAFT，开售前脚本中断，重跑先验证该场次布局、票档和时间，复用原 ID 后完成开售。HTTP 参数/数据库约束错误及 409 沿用业务 API；响应丢失或并发执行后可重跑按代码恢复，本脚本不承诺并发初始化调用都成功。

## 可重复验证与证据

~~~powershell
.\scripts\verify-galaxy-seed.ps1
~~~

默认使用 VERIFY 和 VERIFY-R 两个独立验证命名空间，保留记录供检查；不修改 DEMO 或清库。验证脚本覆盖：

1. 首次创建及每场完整性校验；重跑前后逐记录比较 ID、数据、时间，传不同 BaseTime 仍完全不变。
2. 将验证场馆池座 A1 坐标改为 999.125，种子拒绝且不覆盖，旧快照不变；finally 恢复来源坐标。
3. 首次准备只有一个已提交、尚未开售的售票 DRAFT 场次，运行种子补齐三个场次，保持原 ID/基准并完成开售。已存在验证命名空间时复用，不反复制造中间状态。

这是实际 API 与数据库验证，第三项是构造中间状态的恢复测试，不是杀进程实验。强行终止验证脚本可能来不及执行 finally；此时按脚本记录恢复 A1 原坐标，或用新命名空间，不能清空历史。

实际执行时间、环境和 SQL 核对见[第二周周报](../progress/week-02.md)。738 个快照说明数据完整性，不能据此声称性能或高并发。账号、座位图、连座、锁座、支付、电子票与核销将在对应阶段实现。
