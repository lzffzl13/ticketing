## 已确认与已实现

项目负责人于 2026-10-05 确认[第三周方案](../design/week-03-seat-recommendation-review.md)：只读 REPEATABLE READ 查询、实时分段扫描、区域中心距离及稳定破同分排序，记入 ADR-0007；连座/孤座沿用 ADR-0002。没有新增数据库表或迁移，Flyway 仍为 V1，没有引入 Redis/MQ。

- `GET /api/sessions/{id}/seat-map` 返回完整区域/排/座位快照、坐标、过道、票档、票价和库存状态。`selectable` 独立综合 ON_SALE、AVAILABLE 与票档启用；DRAFT/STOPPED 保留布局。
- `GET /api/sessions/{id}/recommendations` 按正整数人数、可选区域/票档提供确定性候选；默认返回 5 组，展示上限 20。合法但无结果返回空数组和诊断；非法筛选 400、未知场次 404、非销售状态 409。
- catalog 编排同一个只读事务里的场次、票档和座位读取；inventory 承担纯规则和算法，不跨模块访问 Mapper。查询不加行锁、不写库存、响应明确 `reservationMade=false`。
- 完整布局先切同区/排/票档/过道/连续座号的 AVAILABLE 段，随后筛选；人数窗口与孤座快捷判断共享同一规则来源。
- 共用规则支持手动自由选座、按整组比较孤座身份差集、允许既有孤座及场次关闭限制。2026-10-08 确认手选不强制连座、无需用户额外开关，内部调用策略见 ADR-0008。第四周最终锁座复用此组件，但本周没有实现订单或库存写事务。
- 候选使用全区域布局的边界框中心；平均坐标固定 12 位 HALF_UP、BigDecimal 计算距离平方；输入顺序改变不影响输出。
- W3 专用 API 演示、固定种子的 1,000 / 5,000 / 10,000 座纯算法生成器和实验脚本已实现；说明见[导读](../development/seat-recommendations.md)。
