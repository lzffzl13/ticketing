# ADR-0008：系统推荐保证连座，手动选座不强制连座

- 状态：已接受，项目负责人于 2026-10-08 确认
- 日期：2026-10-08（Asia/Shanghai）
- 调整范围：替代第一周“多人购票默认要求连座，消费者可关闭”的普通选座交互规则；ADR-0002 的孤座规则及 ADR-0007 的只读推荐方案继续有效

## 业务问题与备选

消费者手动指定座位时，已经表达了想购买哪些位置。例如 6、7 号之间有过道，手选 5、6、7 可能正是消费者的意图。再要求消费者关闭“要求连座”开关，会使手动自由选座产生多余步骤；系统将该组合标为连座推荐则会误导消费者。

| 方案 | 取舍 |
| --- | --- |
| 多人购买默认连座，手选时由消费者关闭开关 | 可以表达连座意愿，但手选仍需额外操作，容易被默认值意外拒绝 |
| 按选座方式确定连座约束 | 推荐负责保证连座，手选尊重明确选择；手选位置不连座时可给出非阻断提示 |

采用第二种方案。

## 决策与共同不变量

- 系统连座推荐始终满足同区域、同排、同票档、连续座号且不跨过道，不增加非连座自动推荐或用户开关。
- 手动选座不强制连座，无需额外关闭开关；允许不连续、跨过道、跨排、跨区域或跨票档选择同一场次的座位。
- 两种方式都要求场次在售、每个票档启用、全部所选座位可售；默认禁止制造新孤座，允许购买既有孤座，是否放宽孤座规则仍由场次配置决定。
- 手选的孤座判断仍以同区域、同排、同票档、不跨过道的连续可售段为边界，按完整选择集合比较前后孤座身份。
- 两种方式最终下单都重新校验最新状态并整组锁定，全部成功或全部失败；手选自由不会放宽并发和原子性要求。

例：同排 1-6 号在左侧、7-10 号在右侧且全部可售，手选 5、6、7 后剩余 1-4、8-10，没有新孤座，纯规则允许。该组合跨过道，不能作为连座推荐。如果右侧只有 7-8 号，则手选相同组合留下新孤座 8，默认拒绝。

消费者修改推荐组合后，应按手动选择处理。界面可以提醒“所选座位不连座”，但不能仅因此阻止手选购买；消费者演示界面尚未实现，该提示不增加本次开发范围。

## 实现边界与验证

现有 `SeatSelectionRules.validate` 已通过内部参数支持两种校验：手选 `requireAdjacent=false`，推荐组合最终校验 `true`。该参数保留为调用策略，不作为普通购买的用户开关；`forbidNewOrphan` 继续来自场次配置。推荐引擎始终枚举连续可售窗口，无需改变算法。
