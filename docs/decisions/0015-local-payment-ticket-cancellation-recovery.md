# ADR-0015：本地支付、原子出票、安全取消与恢复

- 状态：已接受
- 日期：2026-10-10
- 确认：负责人分别对支付/票结构、取消与订单恢复信息、恢复参数和领取协议回复“采纳建议”。

## 背景与取舍

渠道已收款但本地出票失败时，必须保留渠道事实并重新应用。取消不能依据旧查询或未知状态释放库存。单纯调用重试不能检测中断，多个恢复入口还可能重复累计同一次失败。

采用 MySQL 本地支付记录与电子票、一个完整结果事务，以及订单级持久恢复信息。相比内存重试和到期直接释放，多出短事务、领取字段与恢复入口，但能验证中断、乱序和安全释放；不增加 MQ 或独立服务。

## 支付与票

- V4 新增 payment_record / ticket，不改已经执行的 V1–V3。支付绑定后端订单金额与原截止；(order_id, request_key) 唯一，原键返回原尝试，失败后新键重试不续期。
- 可空生成列唯一约束保护每订单最多一笔 INITIATED / PROCESSING / SUCCEEDED 的占用记录，从而保证最多一笔进行中及一笔成功，并禁止成功后新增进行中记录；FAILED / CLOSED 保留历史。
- 每订单项永久唯一票；VALID / REFUNDING / CHECKED_IN 占用座位唯一，REFUNDED 退出占用。复合外键绑定订单项、订单、场次和座位；本轮只签发/查询 VALID，不实现二维码、退款或核销。
- trade 调用 inventory / ticketing 服务；ticketing 不反向访问 trade。本人票查询由 trade 验证归属，在同一只读快照内查询票。
- 成功结果在一个本地事务内更新支付、订单 PAID、锁 CONSUMED、全部座位 SOLD（核对原持有者并清持有者）和每项一票。场次→订单→支付→锁组→座位顺序加锁，READ COMMITTED，锁后重验。重复和乱序共用同一幂等入口。

## 取消

- 先保存取消意图 USER / TIMEOUT，阻止新支付；事务外查单/关单，再重新加锁读取全部支付与持有者。
- 无支付尝试可直接取消；全部支付确定 FAILED / CLOSED 才可取消并整组释放。成功优先出票。未知/失败保持 PENDING_PAYMENT / ACTIVE / HELD；重复取消返回当前持久状态。
- 取消意图与恢复字段放订单；渠道交互期间不持有库存、订单或渠道行锁。

## Q-06

- 第四周提供运营主动恢复接口，第五周自动扫描复用同一服务。只恢复原支付编号；查无交易且未到期/无取消意图则按原编号补发，否则关闭原编号防止迟到发起。
- 每订单用随机尝试 token 和 60 秒租约领取处理权。未过期租约不能抢占；租约过期可接管。旧处理者仍可幂等应用可信事实，但不能覆盖新领取、累计失败或清除新 token。
- 完成结算核对 token 并一次性清 token。同一次失败仅累计一次。明确失败后创建新支付立即刷新恢复代次，不被旧租约阻止。过期未完成租约在重领时记录一次中断故障。
- 意图提交即保存恢复时间。正常 PROCESSING 不计失败；完整查单/本地处理无故障后清连续失败与异常起点，正常复查在 min(now+5 秒,原截止)。到期/取消仍须关单成功，关单失败不清异常。
- 通知结果应用可在已有领取下进行；只有本次 token 所有者结算故障计数，没有领取的失败保留异常起点、错误与恢复时间。旧支付或旧状态快照不能证明当前尝试已健康，不能清除当前补发/出票异常。
- 第 1–5 次实际故障后的间隔为 5、15、30、60、120 秒；第 6 次或持续实际异常达到 10 分钟标记人工介入，暂停普通自动尝试。矛盾支付事实立即标记人工核查。
- 运营主动恢复可越过退避与人工标志，但遵守活动租约。只能查事实、修复依赖及重试同编号；不能强行改未支付或释放未知支付座位。
