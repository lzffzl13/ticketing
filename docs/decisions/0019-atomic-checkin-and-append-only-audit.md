# ADR-0019：原子核销与每次扫描独立审计

- 状态：已接受
- 日期：2026-10-18（Asia/Shanghai）
- 确认：负责人对第六周两组建议回复“两组都采纳，直接编码（推荐）”。
- 依据：[第六周评审](../design/week-06-checkin-consistency-review.md)。

业务问题是多入口扫描同一张票只能放行一次，并能解释每次失败。比较客户端请求键重放原响应与每次扫描独立审计后，选择后者：首次 SUCCESS，后续 ALREADY_CHECKED_IN，副作用幂等、审计逐次追加。响应丢失时查询原成功记录，系统错误不得作为放行依据。

新增 V6 checkin_record，关联工作人员、所选场次、可空原票，保存服务端请求标识、UTC 微秒时间、结果与凭证 SHA-256 摘要；不存在场次保留原提交编号。原票码、Bearer、密钥不持久化到审计。生成列唯一约束限制每张票最多一条 SUCCESS。

CHECKER 可提交核销；CHECKER / OPERATOR 可按场次、票、时间和游标查询。格式错误和权限拒绝位于受理前，不进入业务扫描审计；已受理的业务拒绝以结果返回并提交失败审计，不能抛业务异常导致审计回滚。

验真后关联原票，场次→订单→座位→票方向加锁，READ COMMITTED 短本地事务内重新读取时间，检查当前场次、半开入场窗口、票状态及已付订单/已售座位。旧退款票先按原票状态拒绝，不访问其已重售座位。VALID→CHECKED_IN 与 SUCCESS 审计同事务，写入失败整体回滚。座位继续 SOLD，支付和历史锁不变。

最后一张未退款票核销且其余票均 CHECKED_IN / REFUNDED、无未决退款时，同事务把订单归集 COMPLETED；已受理退款在其他票已核销后成功，也按这一既有完成条件汇总。全部退款仍为 FULLY_REFUNDED。截止后未到场订单的批量完成归集暂缓，作为限制保留；票码超过截止仍不能核销，不从未归集状态推断还能入场。

自动化覆盖真实核销、双入口、退款/核销锁等待跨边界、重售旧码、时间微秒边界、审计回滚与权限。接受方案不代表实现或执行通过，实际证据记第六周周报，学习验收单列。
