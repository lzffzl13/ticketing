# ADR-0010：以消费者和请求编号识别同一次购买

- 状态：已接受，项目负责人于 2026-10-08 明确采纳下单幂等建议
- 依据：[第四周评审](../design/week-04-order-hold-review.md)的幂等章节及响应丢失业务例子

## 问题与取舍

10:00 下单已提交，订单支付截止为 10:15，但响应丢失；10:01 用户重试应找到原订单，不能新建订单或把期限改成 10:16。只禁按钮无法覆盖网络重试，按座位组合判断也不能区分重试与取消后重新购买。

采用客户端为每次购买意图生成请求编号、重试沿用，后端持久化成功订单与编号的关联。接受保存请求内容摘要及处理冲突的成本。

## 决定

- 幂等范围为当前消费者 + 下单请求编号；不同消费者可使用相同编号，同一消费者跨场次仍共享该编号空间。
- 同编号、同场次、同选座方式与同座位集合返回原订单当前状态和原截止时间，不再落单或续期。座位输入顺序不改变购买意图。
- 编号已经绑定成功创建的订单后，内容变化返回冲突，不覆盖原订单。新的购买意图使用新编号并重新检查库存。
- 取消、到期或暂停后的相同请求仍返回原订单，不能用重放重新占座。
- 数据库对消费者与请求编号建立唯一约束，编号与订单在同一下单事务内保存，防止同时到达的相同请求产生两张订单。
- 校验失败或整事务回滚不保留成功结果；未形成订单时可用同编号重试。方案不永久绑定失败请求的内容。
- 客户端不知道是否成功时保留原编号和原内容重试，不能把网络超时直接视为未落单而换编号。

并发锁座仍由 ADR-0009 保护；幂等不替代库存校验。跨场次的同编号竞争由唯一约束仲裁，失败方完全回滚后读取已提交胜者并核对请求，不能在失败事务中吞异常继续写入。

## 验证与范围

最低场景为连续/并发重放、同编号改内容、座位顺序变化、不同消费者、同消费者跨场次竞争、响应丢失重试、回滚后重试及不续期。

该方案已实现并通过第四周首个闭环测试，执行证据见第四周周报。六表结构、完整事务及登录随后另获负责人确认，分别记录 ADR-0012 / 0013；本 ADR 继续只定义购买请求身份。
