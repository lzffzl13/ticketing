# ADR-0005：七表结构与同步场次快照

- 状态：已接受，项目负责人于 2026-10-04 确认
- 方案依据：[七表评审方案](../design/week-02-schema-review.md)

## 问题与不变量

模板可以维护和删除，场次布局及价格必须独立；场次、票档、全部座位整体创建，同一场次不能复制两套座位。可售位必须有本场次票档和正数金额，不可售位仍保留布局。

## 决策与备选

1. 复制布局、名称和价格，不在查询时关联实时模板。保留来源 ID，但不建立来源外键；接受删除来源后无法回查原记录的代价。其他归属关系用外键限制错误关联，不级联删除历史。
2. catalog 编排同一 MySQL 本地事务，调用 venue 和 inventory 的服务；同步生成，不采用独立生成接口或异步任务。
3. 创建事务使用 REPEATABLE READ 普通查询读取一致版本，先读取内存值再插入快照。并发修改允许继续进行，本次可以采用修改前的完整布局；暂不使用场馆写锁或模板版本模型。
4. 唯一场次代码及唯一快照键防重复。重复代码返回 409，按代码查询已有结果；不建立请求幂等记录表，不承诺原响应重放。
5. 新场次为 DRAFT，首次开售记录 first_opened_at。曾开售场次的布局、价格及入场时间冻结，STOPPED 不恢复编辑资格。开售与启停接口在后续任务实现。
6. 金额用 DECIMAL / BigDecimal 且首版必须为正数，时间统一 UTC；座号为正整数，排排序与过道分段显式保存。

## 本次实现边界

七表迁移、场馆/区域/模板维护、演出创建、DRAFT 场次和快照查询；以真实 MySQL 测试证明隔离、约束、回滚及重复创建。锁座、销售启停、票档修改、登录令牌继续在对应任务实现，不提前宣称完成。

数据库 DDL 可能隐式提交。迁移失败先核对实际结构，不自动 repair、不删除开发卷。详细字段与备选方案保留在评审方案中，测试证据在第二周进度记录中更新。

后续配置修改、销售启停和票档开关见 [ADR-0006](0006-serialize-session-management.md)；这里的实现边界描述首次快照闭环。
