# ADR-0006：场次管理写操作与首次开售冻结

- 状态：已接受，项目负责人于 2026-10-05 确认建议方案
- 依据：[配置与销售方案](../design/session-sales-review.md)

## 问题与决定

改配置先读 DRAFT、另一个事务开售、前者继续改价，会突破 ADR-0005 的冻结边界。管理写操作在同一本地事务中首先 SELECT session FOR UPDATE，等待后按当前状态校验，再修改本场次配置、销售状态或票档开关。配置更新同时修改票档及关联座位的名称/价格快照，任何异常全部回滚。inventory 服务加入调用方事务，不跨模块访问 Mapper。

备选是新增版本号和条件更新，让冲突方重读重试；暂选行锁以避免版本字段及客户端重试协议。代价是同一场次的管理操作短暂串行。不同场次不共用这一行锁。物理模板读取继续采用 ADR-0005 的普通一致性读。

## 操作边界

- DRAFT→ON_SALE→STOPPED→ON_SALE。first_opened_at 只首次写入，暂停、恢复、重复设置都保持；不能退回 DRAFT，不能从 DRAFT 直接暂停。
- PUT 设置当前 ON_SALE/STOPPED 无副作用成功，不引入请求幂等记录表。
- 首次开售前可修改时间、孤座规则、已有票档名称/价格及已有场次座位票档/可售性；曾开售后这些配置整体冻结，暂停不解冻。不增删或重生成座位，不修改物理模板。
- 开售/恢复时至少有一个 AVAILABLE 且所属票档 enabled 的座位，否则 409。重复设置已处于 ON_SALE 的目标是无副作用返回，不重新做开售校验。
- 票档 enabled 可独立启停，不改变快照或库存状态，允许全部停用。未来下单入口必须重新检查场次状态与票档开关，本轮尚无下单实现。

无需新增数据库结构或修改已执行 V1。验证涵盖状态迁移、配置原子性、冻结、重复目标和两个真实事务的开售/改价竞争；执行证据见第二周周报。
