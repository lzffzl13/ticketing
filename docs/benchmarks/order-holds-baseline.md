## 目标与对照

观测已确认的完整 MySQL 下单实现：同场次行锁、READ COMMITTED 最新重验、共用选座规则、整组条件锁座、订单/锁/成交快照同事务，以及提交后结果返回。每个座位规模下以并发 1 作为串行对照，并记录并发 4、8 的有限波次结果。

本实验为当前实现建立后续对照，不比较尚未实现的 Redis/MQ 方案，不根据有限波次宣称生产容量或优化收益。相同场次的不同座位请求仍共享场次行锁；提高线程数不意味着这些写入可以同时进入库存修改步骤。

## 实际环境

Windows 11 家庭版中文版 10.0.26200，amd64；Intel Core Ultra 5 336H，系统报告 12 核 / 12 逻辑处理器，可见内存 33,873,752,064 字节（约 31.55 GiB）。Temurin 21.0.12.1+1、Maven 3.9.9；本机 Docker MySQL 8.4.11，独立 `ticketing_test:3308`，Hikari 最大连接数 **5**。连接默认隔离 REPEATABLE-READ，下单写事务显式 READ COMMITTED。

单 Spring 测试进程执行服务调用；并发 8 超过连接池上限，因此部分请求还会等待连接。开发应用同时运行，演示与基线时段有交叠，共享机器资源；本次没有隔离机器负载、控制冷缓存或执行多轮独立 JVM 对照。

## 数据与并发模型

默认 100 / 500 座；1 个区域、1 个票档，票价 380.00；每排 20 个启用座位、一个过道段，行名为 R0000 起的确定性编号。没有随机不可售位。禁止新孤座；每请求购买两个同排相邻座位，按照 1/2、3/4 等对齐座位对分配，任何波次顺序均不会制造单个余座。

每个规模/并发档位使用独立场次，但同一档位所有工作线程购买同一个场次；同一个消费者使用不同请求编号。各波次等全部线程抵达屏障后共同放行，等本波次所有请求完成后才开始下一波，不按外部固定 RPS 发压。默认每档预热 1 波、正式 4 波；每波请求数等于并发数。默认正式样本为每规模 4 + 16 + 32 = 52 条，两规模合计 104 条；预热共 26 条，排除于指标。

每个请求使用未占用的独立两座对，所有成功请求保留 HELD，不释放重用；所以不同并发档位最终占用数不同。该观测同时包含有限波次的调度、连接池等待及逐渐增加的占用，不能视为只改变锁等待的严格因果实验。实验不测重叠抢座、不同场次的并行分片、支付/取消竞争；这些正确性问题由自动化测试另行验证。

## 计时与验证

用 `System.nanoTime` 包围完整 `OrderService.create` 调用。包含请求规范化与幂等初查、获取连接、场次行锁等待、事务内规则重验、订单/锁/库存写入、事务提交及结果加载；不包含 HTTP、登录、造数、屏障等待、预热、结果断言或输出文件写入。JVM/GC 使用默认设置，不强制 GC，调用期间暂停计入耗时。

延迟输出平均数、中位数与 P95，分位数使用 nearest rank：排序数组的 `ceil(n*q)-1` 位置。默认样本较少，尤其并发 1 仅 4 条，分位数只描述本次样本。

波次总耗时从统一放行开始，到所有 future 返回为止，包括线程调度和收集结果。观测吞吐为“全部正式成功订单 / 正式波次耗时之和”，排除场次准备与波次间隙；它是该有限服务调用实验的完成速率。

每个档位结束后通过真实 MySQL 检查订单数量、每单两条订单项、预期 HELD/AVAILABLE 数量、当前持有者与 ACTIVE 锁的同场次关联。全部订单必须是新创建，不能把同键重放计为成功购买样本。

## 隔离与复现

脚本只构造本机 `ticketing_test` JDBC URL 与固定测试账号。运行器写入前再执行 `SELECT DATABASE()` 严格校验库名；没有清库、Flyway clean、删除历史交易、关闭外键或删除卷。请与完整测试串行执行，完整测试夹具会清理专用测试库。

```powershell
.\scripts\start-infra.ps1 -IncludeTest
.\scripts\benchmark-order-holds.ps1
```

脚本只编译并显式运行 `OrderHoldBenchmarkExperiment`，不重新执行整套回归。默认每次生成新的 `HB...` 命名空间，测量新的成功下单；重跑保留旧数据，新实验创建新夹具。所有非敏感请求在提交前保存到 requests CSV，可根据 namespace / session_id / request_key 查回部分成功。失败环境记录为 FAILED，不把部分结果作为完整通过。

自定义规模必须是 20 的倍数，并保证每档 `2 × (预热波数 + 正式波数) × 并发数 <= 座位数`，例如：

```powershell
.\scripts\benchmark-order-holds.ps1 -SeatCounts 500,1000 -Concurrency 1,4,8 -Batches 20 -WarmupBatches 2
```

输出位于 `.local/order-holds-{UTC时间戳}.*`：environment JSON 保存操作系统、CPU、内存、JDK/Maven、参数；database JSON 保存实际 MySQL 版本、库名、Hikari 池上限、事务设置和夹具身份；summary CSV 保存档位汇总；samples CSV 保留纳秒原始样本；requests CSV 保留预热及正式请求身份。文件不记录密码或令牌。
